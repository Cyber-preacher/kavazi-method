# Phase 01 methodology

[Plan](IMPLEMENTATION_PLAN.md) · [Evidence](EVIDENCE.md) · [Master methods](../../MASTER_METHODOLOGY.md).

Use isolated temporary repositories and direct CLI invocations. Measure effects, not repeated wording: file contents before/after, tree changes after dry run, exit status and messages, eligible packages, and baseline mismatch rejection. Define behavior in Master Architecture and configuration and state records in Master Technical Core before implementation. Cover malformed records and path boundaries alongside successful adoption.

Source and installed-payload regression tests must run with standard-library Python. Preserve failed results in evidence. Inspect full phase scope and integrations after fixes; a fresh independent review is the closure gate, not a packaging linter. Semantic review and recorded executable acceptance are separate. Packaging availability in a provider UI, Git initialization, and cross-platform execution must be reported only if actually observed.

For the revised intake route, compare raw short and multiline briefs with captured text, map existing Technical Core files without overwriting them, and verify both autonomous advancement and checkpoint refusal/explicit recorded approval. Inspect the generated reasoning order and requirement-to-mechanism traceability. Evaluate an independent realistic brief through the installed skill before claiming the agent instructions are usable; this remains a scoped local observation, not a guarantee of uninterrupted autonomous execution.

For the editorial follow-up, review the human setup guide and agent entry instructions as separate reading paths. Follow the documented commands in a temporary repository, inspect the generated masters and phase package, and verify that advanced procedures are easy to find. Keep historical input and observations intact. Check changed links, skill metadata, CLI help, and archive contents; renew review and acceptance for the resulting baseline.
