# Phase 03 methodology

[Plan](IMPLEMENTATION_PLAN.md) · [Evidence](EVIDENCE.md) · [Master methods](../../MASTER_METHODOLOGY.md).

Verify current account, repository availability, and predecessor closure before changes. Compare ruleset scopes, actor ID, bypass modes, mandatory checks, merge methods, and destructive-update restrictions against the user request and GitHub API. Test exact embedded route code with positive, negative, fork, malformed, and injection-shaped event fixtures.

Run required regression and structural checks, build the archive, and review distribution/source consistency. Publish from an isolated Git export without touching protected local metadata or copying caches/secrets. Inspect the staged paths. After repository creation, read back refs, settings, identities, and rules. Observe actual workflows on branch-to-dev and dev-to-master PRs and a failing route to master. Record URLs, revisions, check conclusions, failures, and limits. Do not infer other-user rejection from owner credentials.

Review code, tests, workflows, rules, public guidance, masters, records, exported source, and hosting interactions together. Use stable finding IDs; fix demonstrated defects, justify refactors, verify, then review the full resulting scope afresh. Preserve prior acceptance and dated evidence. Record actual reviewer settings when known and complete handoff reconciliation before taking the accepted fingerprint.
